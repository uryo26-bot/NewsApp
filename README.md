# NewsApp

日本語ニュースをRSSから取得し、地域・ジャンルで分類して閲覧するニュースアプリです。

> **開発状況:** 現在はMVPの実装前です。このREADMEは予定している仕様と構成を記載しています。

## MVPの機能

- RSSフィードから記事タイトル、URL、概要、公開日時、提供元を取得
- OpenAI APIで記事を地域とジャンルに分類
- SQLiteに記事と分類結果を保存し、記事URLの重複登録を防止
- 地域とジャンルをそれぞれ選び、両方を指定した場合はAND条件でニュースを絞り込み
- 新しい記事から順にカード形式で表示し、元記事へリンク
- RSS取得や分類に失敗した記事を、正常な分類済み記事と区別

### 分類項目

地域は **Asia、Europe、North America、South America、Africa、Oceania** から1つ、ジャンルは **Economy、Politics、Technology、Society、Science、Environment、Sports、Culture** から1つ選びます。日本国内のニュースはAsiaに分類します。

### MVPの対象外

地図・GIS・位置情報、ユーザー登録、コメント、お気に入り、推薦機能、英語ニュース、翻訳、高度な検索・分析機能は対象外です。

## 技術構成

| 領域 | 技術 |
| --- | --- |
| フロントエンド | React、TypeScript、Vite、CSS |
| バックエンド | Python、FastAPI |
| データベース | SQLite、SQLAlchemy |
| ニュース取得 | RSS解析ライブラリ、定期実行処理 |
| 分類 | OpenAI API、Python公式SDK |

OpenAI APIキーと利用モデル名は環境変数で設定し、秘密情報をソースコードに記載しません。`.env` はGitにコミットせず、設定例を `.env.example` で管理する予定です。

## 予定するAPI

- `GET /api/health` — バックエンドの稼働確認
- `GET /api/news` — ニュース一覧。`region`、`genre`、`limit`、`offset` に対応
- `POST /api/admin/fetch-news` — ニュース取得の手動実行用。MVPではローカル利用を前提とします

## 開発フェーズ

各フェーズは記載した完了条件を満たした時点で完了とします。完了後に変更内容と確認結果を共有し、ユーザーの確認を得てから次のフェーズへ進みます。条件を満たせない場合は未完了事項と理由を明確にし、次フェーズへ進みません。

### Phase 0：既存環境・要件の確認

**実施内容**

- リポジトリ内のファイル、設定、既存実装、Gitの作業状態を確認する。
- 要件に対する技術構成とディレクトリ構成を提示する。
- 実装上の制約、仕様の曖昧さ、外部サービスやRSSの確認事項を洗い出す。
- この段階ではコードを変更しない。

**完了条件**

- 既存環境と実装の有無が確認され、ユーザーに共有されている。
- MVPの範囲、技術構成、初期の実装順序が明示されている。
- 着手前に決めるべき仕様上の問題があれば、未決事項として示されている。
- ユーザーが計画を確認・承認している。

### Phase 1：バックエンド基盤

**実施内容**

- FastAPIアプリケーションとSQLite・SQLAlchemyの接続を構成する。
- ニュースモデルに、記事情報、地域・ジャンル、分類ステータスを保持できる項目を定義する。
- 記事URLに一意制約を設定し、API入出力用のスキーマを用意する。
- `GET /api/health` と `GET /api/news` を実装する。地域・ジャンルによるAND絞り込み、`limit`、`offset` に対応する。
- 基本的なテストを追加し、ローカルで再現可能な方法で実行する。

**完了条件**

- バックエンドを起動でき、`GET /api/health` が正常時に稼働状態を返す。
- データベースが初期化され、ニュースを保存・取得できる。
- 同一URLを複数回登録できないことをデータベース制約とテストで確認できる。
- ニュース一覧が新しい公開日時順で返り、地域・ジャンルを単独またはAND条件で絞り込める。
- 未指定の絞り込み条件が全件扱いとなり、`limit` と `offset` が機能する。
- 不正なクエリ値に対して適切なエラー応答を返し、テストが通る。

### Phase 2：RSS取得

**実施内容**

- NHKを第一候補として利用可能な公式RSSフィードと利用条件を確認し、採用するフィードを記録する。
- RSS解析、記事情報の抽出、記事URLによる重複排除、データベースへの保存を実装する。
- 取得処理をAPIやフロントエンドから独立して実行できるようにし、1時間間隔の定期実行と手動実行を用意する。
- フィードごとの失敗を処理し、取得失敗がアプリケーション全体を停止させないようにする。

**完了条件**

- 採用フィードのURL、提供元、利用条件の確認結果が設定またはドキュメントに明記されている。
- RSSからタイトル、URL、概要、公開日時、提供元を取得して保存できる。欠落・不正な項目がある記事の扱いも定義されている。
- 同じ記事を再取得してもURLの一意制約により重複登録されず、処理が継続する。
- 手動実行と1時間間隔の定期実行の両方が可能である。
- フィード取得失敗時にエラーが記録され、他の処理やアプリケーションが継続することをテストで確認できる。
- 外部RSSへのアクセスに依存しないテストを用意し、抽出・重複排除・失敗時の挙動を確認できる。

### Phase 3：LLM分類

**実施内容**

- 分類処理を独立したサービスとして実装し、OpenAI APIの接続とモデル名を環境変数で設定する。
- 記事タイトル・概要を使って地域とジャンルを分類し、構造化JSONで結果を受け取る。
- JSONの形式と値を検証し、分類失敗をデータベース上で正常な分類済み記事と区別する。
- APIエラー、不正な出力、設定不足などの失敗を記録して処理を継続する。

**完了条件**

- APIキーが環境変数から読み込まれ、ソースコードやログに秘密情報が出力されない。
- 利用モデルを環境変数で変更でき、分類サービスをRSS取得処理およびフロントエンドから独立して実行できる。
- 有効な結果では地域が6種類、ジャンルが8種類の許可値に限定され、それぞれ1つずつ保存される。
- JSON不正、許可値外の分類、APIエラー、タイムアウト等を失敗として記録し、正常な分類済みデータとして扱わない。
- 失敗記事が記録され、他の記事の分類処理が継続することを確認できる。
- OpenAI APIに接続しないテストで、正常出力・不正出力・API失敗時の検証と保存結果を確認できる。
- 特定地域に分類しにくいニュースの扱いが決定・文書化され、その方針が保存形式とテストに反映されている。

### Phase 4：フロントエンド

**実施内容**

- React・TypeScript・Viteでニュース一覧画面を作成する。
- 地域タブとジャンルタブを実装し、選択条件をバックエンドAPIへ渡す。
- ニュースカード、読み込み中・エラー・空状態を表示する。
- PCでの閲覧を優先しつつ、スマートフォンでも利用できるレイアウトにする。

**完了条件**

- 地域とジャンルの初期選択がそれぞれ「すべて」で、各タブ内の選択が単一選択として動作する。
- 地域とジャンルの両方を指定したとき、API経由でAND条件の結果が表示される。
- 記事タイトル、提供元、公開日時、地域タグ、ジャンルタグ、概要、元記事へのリンクがカードに表示される。
- 記事カードのリンクから元記事を開け、新しいニュースが上に表示される。
- ニュースが0件の場合の空状態、読み込み中、APIエラー時の状態が区別して表示される。
- PCとスマートフォン相当の画面幅で主要な操作と表示を確認できる。
- 地域・ジャンルをフロントエンドで再分類せず、サーバーから返された分類結果を表示する。

### Phase 5：統合テスト・仕上げ

**実施内容**

- RSS取得、重複排除、分類、保存、API取得、画面表示までの一連の動作を確認する。
- API・画面の絞り込み、エラー状態、空状態を含む統合テストを実施する。
- セットアップ、環境変数、起動、テスト、手動ニュース取得の手順をREADMEに整備する。
- 秘密情報や不要な機能が含まれていないか確認する。

**完了条件**

- 新規取得記事が分類され、SQLiteに保存され、画面に表示されるまでの一連の流れを確認できる。
- 同一記事の再取得で重複せず、地域・ジャンルのAND絞り込みと新しい記事順が機能する。
- RSS失敗、分類失敗、APIエラー、データなしの場合に、アプリ全体が停止せず適切な状態を示す。
- 必要な自動テストが成功し、起動・テスト手順を別の開発者がREADMEに従って実行できる。
- `.env` やAPIキーがGit管理対象に含まれず、`.env.example` だけで必要な設定項目を確認できる。
- MVP対象外の機能を追加しておらず、残課題や制約があればREADMEに明記されている。

## 開発上の注意

- RSSフィードの利用規約・取得条件を確認して利用します。
- 記事本文を無断転載せず、タイトル・概要・リンクを中心に扱います。
- 分類結果はバックエンドで検証し、フロントエンドでは再分類しません。
- `region` と `genre` の絞り込みはバックエンドまたはデータベースで行います。
- 分類しにくいニュースの扱いは、分類機能の実装前に仕様を確認します。
